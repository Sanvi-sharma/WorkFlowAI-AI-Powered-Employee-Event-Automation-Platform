# Troubleshooting & Debugging Log
1. Introduction

The development of the Registration Automation System involved multiple stages of design, implementation, testing, debugging, and optimization. During the development lifecycle, several technical challenges were encountered across different components of the system, including Docker, n8n, Google Workspace integrations, Ollama, AI agents, workflow logic, and data synchronization.

Rather than applying temporary fixes, each issue was analyzed to identify its root cause, followed by systematic debugging and implementation of a long-term solution. Every modification was documented to ensure that future maintenance, troubleshooting, and feature enhancements can be performed efficiently without repeating previously resolved problems.

This document serves as the official troubleshooting log for the project and records the engineering decisions made throughout development. It includes the problem statement, observed symptoms, root cause analysis, debugging approach, implemented solution, and the final resolution status for each issue encountered.

2. The objective of maintaining this document is to:

- Provide a centralized reference for all technical issues encountered during development.
- Document the reasoning behind architectural and workflow changes.
- Assist future developers and interns in understanding previously resolved problems.
- Reduce debugging time during future maintenance and upgrades.
- Establish a structured knowledge base for continuous improvement of the automation platform.

# Summary of Major Engineering Decisions

| Decision                                                | Reason                                                                           |
| ------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Switched from OpenAI API to Ollama                      | Eliminated API quota limitations and enabled local inference.                    |
| Adopted Google Sheets as the primary data store         | Simple integration with Google Forms and suitable for workshop-scale operations. |
| Used permanent Registration IDs stored in Google Sheets | Prevents ID regeneration and ensures consistency across workflows.               |
| Configured Code Nodes to run once per item              | Enables independent processing of each participant.                              |
| Eliminated unnecessary Merge nodes                      | Reduced workflow complexity and minimized synchronization issues.                |
| Preserved original JSON objects using spread syntax     | Prevents accidental data loss during workflow transformations.                   |
| Introduced conditional Registration ID generation       | Avoids overwriting existing participant records.                                 |
| Standardized AI output using JSON                       | Ensures compatibility with downstream automation nodes.                          |
| Exposed Ollama on `0.0.0.0`                             | Enables communication between Docker containers and the host AI service.         |
